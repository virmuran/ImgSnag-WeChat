# ImgSnag 安卓版

把「抓微信公众号文章原图」做成了手机上的一个普通 App：**在微信里点分享 → 选 ImgSnag → 图就进相册了**。

不用装 Termux，不用敲命令。

---

## 一、这个 APK 是怎么来的

**代码在你的电脑上，编译在 GitHub 的服务器上。**

原因很实在：安卓打包要 JDK + Android SDK + NDK + Gradle，全下来 2GB 起步，
在 Windows 上配好还得半小时；而 GitHub 的运行器**这些全都预装好了**，
公开仓库还免费、不限量。所以这里不放「打包脚本」，只有一个云端构建配置
（`.github/workflows/build-apk.yml`）。

你只需要**发一个正式版本**（或手动点一次构建），剩下的它自己做完。

---

## 二、怎么拿到 APK

### 方式 A：正式发版时自动合体（推荐）

在 GitHub 上 **Publish 一个正式版本 Release**（exe 和便携 zip 已传好）的那一刻，
构建会自动跑一次，并把 APK **塞进同一个 Release 页面** —— 于是那个版本下
exe、便携 zip、APK 三种形态并排，用户只需要记住一个下载入口：

> 仓库页面 → 右侧 **Releases** → 点最新那个版本 → 下载里面的 `.apk`

**跟你下桌面版安装包是同一个地方、同一个操作。**

### 方式 B：手动触发

> 仓库页面 → **Actions** → 左侧选 **Build Android APK** → 右上 **Run workflow** → 绿色按钮

跑完**不碰 Release**，在这次的构建记录最下方 **Artifacts** 里下
`ImgSnag-APK-x.y.z`（是个 zip，解开里面有 apk）。

> 推送代码**不会**自动构建：曾经每次推送都把 APK 刷到 Releases 的 `apk-latest`
> 滚动预发布位，但预发布对所有人可见，等于把下载入口弄成两个 —— 已取消。

### 怎么知道构建成功了

正式发版时：Release 页里出现了带新版本号的 `.apk` 资产 = 成功。
手动触发时：Actions 里那次构建变绿 = 成功。
如果失败了，去 Actions 里点开那次红色的构建，把 **报错那段**发我 —— 见文末「出问题了」。

## 三、怎么装到手机上

1. 在手机上打开那个 Release 页面（或者把 apk 用微信/QQ 传给自己，手机上下载）
2. 点开下载好的 `ImgSnag_<版本>_android_arm64.apk`（文件名里的版本号跟着版本走）

**红米 / 小米（HyperOS）会拦一下**，这是正常的：

> 弹窗提示「为了安全，你的手机不允许安装未知应用」
> → 点弹窗里的 **设置** → 打开 **「允许来自此来源的应用」**
> → 返回，再点一次安装
>
> 如果系统还提示「此应用未经安全检测」，选 **「仍然安装」**。
> 装完后建议把这个开关**关回去**（安全习惯）。

首次安装可能还要确认「是否允许安装应用」，允许即可。

### 装不上？三个最常见原因

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 提示「解析包出现问题」 | 下载不完整（多半是用内置浏览器下载被拦了） | 换用手机自带的浏览器/文件管理器重新下载 |
| 提示「应用未安装 / 与已有应用冲突」 | 之前装过**用别的密钥签名的**同名应用 | 先卸载旧的那个再装 |
| 提示「此应用与你的手机不兼容」 | 手机不是 arm64 架构，或系统低于 Android 10 | 红米 K80 是 arm64 + Android 15，正常不会遇到 |

## 四、怎么用

App 打开后是一个**网页界面**（为什么是网页，见文末「几个刻意为之的选择」）。

### 用法一：微信里直接分享（主用法）

> 微信打开文章 → 右上角 **…** → **分享**（或「复制链接」旁边的分享）
> → 在分享菜单里找到 **ImgSnag** → 点它

App 会打开并自动开始解析。**抓完停在预览页**，让你看一眼再决定存哪些。

分享菜单里应用很多，ImgSnag 可能在**第二页**或者要点「更多」。

### 用法二：自己贴链接

1. 复制文章链接（哪儿复制的都行）
2. 打开 ImgSnag，把链接粘进**顶部的输入框**，点「解析图片」
3. 同样抓完停在预览页，看完再存

### 用法三：从剪贴板

在浏览器里打开文章 → **复制正文**（或复制链接）→ 打开 ImgSnag → 点 **「从剪贴板」**。

带 HTML 的复制内容也能解析（正文里的图片地址就在里面）；只有纯文本链接也一样能用。

### 界面长这样

```
┌────────────────────────────────┐
│ [ 粘贴公众号文章链接… ] 从剪贴板 │
│ [ 解析图片 ]                    │
│ ┌────────────────────────────┐ │
│ │ 保存原图            [开]   │ │  首页的三个卡片 / 开关
│ │ 自动跳过小图        [开]   │ │
│ │ 版本更新          [检查]   │ │
│ └────────────────────────────┘ │
├────────────────────────────────┤
│ 找到 12 张图                    │
│ 已自动跳过 1 张小图…            │
│  ┌──┐ ┌──┐ ┌──┐ ┌小┐           │  缩略图网格
│  │  │ │  │ │  │ │  │           │  点一下 = 看大图
│  └──┘ └──┘ └──┘ └──┘           │  点右上角圆圈 = 勾选
│   …                        ↖小标│
├────────────────────────────────┤
│  全选   已选11张   复制   保存  │
└────────────────────────────────┘
```

- **默认全选**（小图除外）：想全存就直接点「保存」
- **点缩略图 = 看大图**，**左右滑动就能翻上一张/下一张**（放大状态下变成平移图片，
  不会误翻）；大图页两侧也有箭头按钮，右上角能勾选，还能**只存这一张**
- **点右上角的小圆圈 = 勾上／取消**（手机上把"看大图"和"勾选"分成两件事，
  免得想看的时候反而把它取消了）
- **全选／全不选**：几十张的时候不用一个个点
- **复制**：把这篇的名字复制走，**不含前面的日期编号** —— 相册里的文件夹叫
  `2026-10-07_153045_标题`，它给你的只有后半截（解析中或没有标题时按钮是灰的）
- **返回键 / 侧边滑动返回**：关大图 → 退回上一页 → 再滑才退出 App，
  和平时用手机的习惯一致

### 两个开关（首页）

- **保存原图**：开＝存原图档（清晰、费流量）；关＝存压缩档（省流量）。
  文章里同一张图本来就有这两个档位，这里只是决定"存的时候用哪个"。
- **自动跳过小图**：表情、二维码、分割线这类小图**默认不勾选**，并在缩略图上
  打一个「小」标。**不是删掉** —— 想存就把它们勾上，照样存。
  判据是体积（默认小于 12 KB），在首页关掉开关就完全不做这件事。

### 版本更新（首页那张卡片）

打开 App 会**自动查一次**，之后随时可以点卡片右边的按钮手动再查。
查到有新版本**就在 App 里下好、直接点安装**，不用自己去 Release 页面翻。

| 卡片上写什么 | 按钮是什么 | 点下去会怎样 |
|---|---|---|
| 版本更新 / 还没检查过 | 检查 | 刚打开还没查到结果，点一下再查 |
| 版本更新 / 查不到 GitHub 上的发布 | 重试 | 网络不通或仓库地址有变动，点一下重查 |
| **有新版本** v…（标题变蓝） | **更新** | 当场下载新包，卡片变成进度 |
| 正在下载更新 3.1 MB / 19.8 MB（16%） | 取消 | 反悔就停，已经下到一半的文件会删掉 |
| **更新已下载** v… 已就绪 | **安装** | 交给系统安装器，弹「是否安装」→ 点安装 |
| 下载失败 / 没能下载下来… | 重试 | 卡片右边同时出现「去网页下载」兜底 |
| 版本更新 / GitHub 上最新：v… | 去看看 | 只告诉你远端有什么，**不下结论**（见下） |
| 已是最新 | 再检查 | 比过了，没有更新的 |

**首次点「安装」会被拦一下**：系统要你先允许 ImgSnag「安装未知应用」
（跟第三节里手动装 apk 是同一个开关，只是这次授权对象是 ImgSnag 自己）。
App 会直接把你送到那个设置页，开完**退回来就自动接着装**，不用再点一次。

> 下下来的包会先**核对字节数和 sha256 摘要**再交给安装器 ——
> 公司网络/加速器偶尔会把大文件截断（20 MB 的包下到 12 MB 就结束），
> 以前这种半截包装上去只会报「解析包时出现问题」，看不出是下载的锅。

> **为什么偶尔会有"问不到本机版本"**：判断有没有新版，**主要比版本号**
> （你手机里这个 App 的版本 vs GitHub 上下载包名里的版本号），
> 只有当版本号认不出来（或两边的版本号一样、是同一版本重新构建）时，
> 才退回去比「GitHub 上那个包的构建时间 vs 你手机里这个 App 的安装时间」。
> 少数机型/系统对"安装时间"这个字段给得不准（返回 0 或者一个明显不合理的时间），
> 版本号又认不出来时，卡片就只报远端版本、不下结论 ——
> 宁可不说话，也不乱说"有新版本"把你骗去白下一趟。

> **还有一个兜底入口**：卡片右边的「去网页下载」，跳的是最新正式版本的
> Release 页。在电脑浏览器里打开这个界面时只有这条路，
> 因为电脑上装不了 apk。

### 下载历史（右上角图标）

每次解析都会留一条记录，写着文章标题、时间、张数、有没有抓成功。

- **点开** = 重看上一批图（缩略图还在），也能**补存**当时没勾的
- **重抓** = 文章更新了，再解析一次
- **删掉** = 只删这条记录，相册里的图不动

> 只留最近 5 次，旧的自动清理。原图档和图本身不留（几十兆，没必要），
> 所以历史里点开看到的是缩略图 —— 想存原图就点「重抓」再存。

### 为什么抓完停在预览页，不直接进相册

以前是「分享进来 → 直接全抓进相册」。问题是文章里常混着表情包、二维码、
分割线小图这类不想要的图，抓完还得自己去相册一张张删。

现在**抓完先给你看，勾完再存** —— 相册里不会再进垃圾。

### 界面起不来怎么办

如果一直显示「正在启动…」或提示「界面没能启动」，遮罩上会留两个按钮：

- **重试**：再起一次
- **直接抓取**：不走网页 —— 读剪贴板里的链接 → 抓图 → 直接进相册
  （老路子，能用，但没有挑图这一步）

日志里 `❌` 开头的就是原因，**长按可以选中复制**，发我比截图好查。

## 五、图片存到哪儿

```
手机存储 / Pictures / ImgSnag / 2026-10-05_175300_文章标题 / img_01.jpg
                                              ├── img_02.png
                                              └── …
```

- **一篇一个文件夹**，名字是「日期_时分秒_标题」，按名字排序就是时间顺序
- 文件名按**真实格式**给扩展名（`.png` 就是 `.png`，不会都叫 `.jpg`）
- 存的是**原图档**（微信公众号图片的最高画质那一档），抓不到原图才退压缩档
- 手机相册会自动扫到，不用手动刷新

> 在「相册／图库」App 里通常能在 **相册 → 全部／Pictures → ImgSnag** 找到。
> 系统自带的「文件管理」里也能按上面那个路径翻到。

## 六、权限与隐私

清单里一共两条权限：

- **网络访问（INTERNET）** —— 抓公众号文章和图片都要联网
- **安装应用（REQUEST_INSTALL_PACKAGES）** —— 只为「应用内更新」这一个用途：
  下载完新版本后把包交给系统安装器。**App 不会在后台悄悄装任何东西** ——
  每一次安装都是你自己点的「安装」，而且首次还得你在系统设置里手动开一次开关。
  （自用分发不涉及应用市场上架；上架的话这条权限会被额外审查。）

其余一律没有：

- 没有「读写手机存储」权限 —— 写相册走的是系统的 MediaStore，
  Android 10 起应用新建自己的图片不需要存储权限
- 没有账号、没有统计、没有联网上传；图只从微信 CDN 下到你手机
- 抓的都是**公开文章**的图片
- 下载的安装包只放在应用自己的私有目录（`files/update/`），
  交给安装器时走 FileProvider 临时授权那一个文件 —— 别的应用读不到

## 七、更新与卸载

**更新**：首页那张「版本更新」卡片会告诉你有没有新的（见第四节）。

点「更新」→ 当场下载（卡片上有进度）→ 下完按钮变「安装」→ 点它 →
系统弹「是否安装」→ 安装。**覆盖安装，已经抓进相册的图不会丢。**

首次点「安装」时系统会要一次「允许 ImgSnag 安装未知应用」，App 会直接把你送到
那个设置页；开完**退回来会自动接着装**，不用再点一次。

> 下载完的包会先核对**字节数**与 **sha256 摘要**，对不上就当场丢弃、不交给安装器
> （截断的包装上去只会报「解析包时出现问题」，看不出是下载的锅）。
> 下载目录里**只留最新那一个包**，下次更新会把上一个清掉，不会越攒越多。

> 签名密钥是固定的、提交在仓库里 —— 换密钥会让新版本装不上旧版本，
> 那种情况只能卸载重装（应用数据与历史会丢，相册里的图不受影响）。

**卸载**：长按桌面图标 → 卸载。已经抓进相册的图片**不受影响**（它们在相册里，
不属于应用数据）。

## 八、出问题了怎么办

先说一件事：**我（写这个 App 的 AI）没法在你的手机上跑一遍** ——
手上没有 JDK、没有 Android SDK、没有安卓设备，本机连编译都做不到。
所以第一次装上很可能有一两个小毛病要修。这是预期内的，不是白折腾。

请按这个顺序给我信息：

1. **构建失败**（Releases 里没出现 APK）→ 把 GitHub Actions 那次红色构建里
   最后 30 行报错贴给我
2. **装不上** → 告诉我弹窗的**原文**
3. **装上了但打不开/闪退** → 告诉我大概是点开就退，还是进了界面再退
4. **分享菜单里找不到 ImgSnag** → 试试用「复制链接 → 粘进输入框 → 解析」这条路，
   能抓说明是分享入口的问题；另外告诉我你是在微信里点「分享」还是「复制链接」
5. **抓不到图** → 把日志里那段文字复制发我（`❌` 开头的那几行最关键）
6. **打开一直转圈、或者界面白屏** → 先点「重试」；还不行就点「直接抓取」
   （它不走网页，一定能用）。然后把这行日志发我 ——
   白屏多半是手机不允许 App 连它自己的本机地址（127.0.0.1），日志里会写明。
7. **点「更新」下不动、或者装不上** → 卡片上会写失败原因（已经是人话，不是异常原文），
   把它复制发我。卡在「允许安装未知应用」那一步的话，告诉我你手机是什么牌子、什么系统 ——
   各家的设置页路径不一样，但这一环是系统管的，App 只能把你送过去。

## 九、给想改代码的人（工程说明）

### 目录

```
android-apk/
├── app/
│   ├── build.gradle.kts              构建配置（compileSdk 36 / minSdk 29 / 只带 arm64-v8a）
│   ├── proguard-rules.pro            压缩规则（当前没开压缩，留着备用）
│   └── src/main/
│       ├── AndroidManifest.xml       权限（联网 + 装包）+「分享」入口 + 回环明文放行
│       ├── java/com/virmuran/imgsnag/
│       │   ├── MainActivity.java     外壳：起本地服务、WebView、分享、返回手势、剪贴板、装更新包
│       │   └── Gallery.java          把图写进系统相册（MediaStore）
│       ├── python/
│       │   ├── imgsnag_web.py        ★ 手写：界面后端（本地服务 / 会话 / 历史 / 更新包下载）
│       │   ├── webui.py              ★ 手写：整个页面（HTML+CSS+JS 单文件）
│       │   ├── imgsnag_android.py    ★ 手写：桥接层（网络 / 证书 / 人话化）
│       │   ├── imgsnag.py            ← 自动同步，别改
│       │   └── web_image_dl/         ← 自动同步，别改
│       └── res/                      布局、文案、颜色、启动图标、网络安全配置、
│                                     FileProvider 路径（xml/file_paths.xml）
└── keystore/imgsnag.p12              自用签名密钥（固定，见 keystore/README.md）
```

### 三层分工

| 层 | 负责 | 为什么不放别处 |
|---|---|---|
| Java | 外壳：起服务、WebView、接收分享、返回手势、剪贴板、把更新包交给安装器 | 这些是安卓平台特有的能力 |
| `imgsnag_web.py` + `webui.py` | 界面：本地服务 + 网页（网格／大图／历史／更新卡片） | 手写；**而且网页在电脑上就能验**（没模拟器也能测） |
| `imgsnag_android.py` | 网络（urllib）、证书、把结果拼成人话 | 手写；平台相关的黏合层 |
| `imgsnag.py` + `web_image_dl/` | 抓取与站点规则 | **与桌面版、Termux 版是同一份文件** |

`web_image_dl/sites/weixin.py`（微信原图档、去水印、正文顺序）是这套程序最值钱也
最容易失效的部分。它被 `android/sync_core.py` **自动同步**到三个地方：

```
web_image_dl/  ──sync_core.py──▶  android/app/                      （Termux 版）
              ──sync_core.py──▶  android-apk/app/src/main/python/     （APK）
```

改了规则之后**必须**跑一次：

```sh
.venv/Scripts/python.exe android/sync_core.py
```

忘了跑也不会出事 —— `tests/test_apk_app.py` 第一条就是逐字比对副本，
不同步当场变红，CI 上也会先跑它再打包。

### 几个刻意为之的选择

- **界面是一个网页，不是安卓控件**。图片网格、点开看大图、缩放、翻页，浏览器天生都有；
  用安卓控件从头写至少要几百行，而且**本机一行都验不了**（没模拟器、没真机）。
  改成网页之后，抓取跑在本地服务上（只绑 `127.0.0.1`），页面在电脑上就能打开、
  能点、能截图 —— 把「只能靠真机发现」的部分压到最小。代价是手机上多了一个
  「App 能不能连自己的回环地址」的前提，所以「直接抓取」那条老路留着兜底；
  清单里也只给回环地址放行了明文 HTTP（`res/xml/network_security_config.xml`），
  没有全局开口子。
- **返回手势用「网页报层级」，不用 `WebView.canGoBack()`**。`canGoBack()` 的
  行为取决于 WebView 内部怎么记 `pushState` 产生的历史条目，**在真机上不可预期**；
  改成网页自己维护一个层级计数（进大图 +1、返回 -1），每次变化通过 JS 桥同步给 Java，
  Java 只看「层级 > 0」就调 `history.back()`，否则才退出 App。
  ⚠ 还有一条**必须**记住的坑：`targetSdk` ≥ 35 的应用默认启用**预测性返回**，
  系统**根本不会调用 `onBackPressed()`** —— 只覆写它，症状是"侧滑直接退回桌面、
  日志里一个字都没有"。正确做法是清单里写 `android:enableOnBackInvokedCallback="true"`，
  并在 API 33+ 用 `getOnBackInvokedDispatcher().registerOnBackInvokedCallback(...)`
  注册；新旧两条路径共用同一个 `handleBack()`，老的 `onBackPressed()` 留着兜底。
  另外**翻页不算一层**：大图里左右翻只 `replaceState`，否则翻 5 张要划 5 次才退得出去。
- **一个 pip 包都不装**。Chaquopy 装包要走它自己的仓库、还得为 arm64 现编，
  是整条构建链路最容易挂的地方；而 `web_image_dl/` 本来就是零第三方依赖的，
  联网用自带的 `urllib` 就够。
- **不做代码压缩**（`isMinifyEnabled = false`）。Chaquopy 的 Python 靠反射调进
  Java，R8 看不见这些调用。省几 MB 换来「某个功能上线后莫名失效」不划算。
- **minSdk 29**。写相册用的 MediaStore `RELATIVE_PATH` 要 Android 10 起；
  有这个就不需要任何存储权限。再往下兼容要写另一套老 API，对自用工具不值当。
- **版本组合锁死**（Chaquopy 17.0.0 + AGP 8.13.1 + Gradle 8.13）。
  这是 Chaquopy 17.0.0 官方 demo 自己的配置。**不要顺手升 AGP** ——
  Chaquopy 插件和 AGP 内部 API 绑得很紧，升级后报的错通常很难看懂。
- **版本号从 `version.py` 读**，不手写。APK 上显示的版本和桌面版对得上。
- **更新是"App 自己下载"，不是"跳去网页"**。安卓完全允许应用下载并安装另一份
  apk（要 `REQUEST_INSTALL_PACKAGES`，首次还得用户手动开一次「允许安装未知应用」），
  所以没必要把用户踢到浏览器里再走一遍"下载 → 找文件 → 点安装"。
  三条约束：
  · **交出去的文件必须走 `FileProvider`**（`content://`）。安卓 7 起用 `file://`
    把文件传给别的应用会直接抛 `FileUriExposedException`，而且报的是"解析包错误"、
    看不出真正原因。开放的目录只有 `files/update/` 一个子目录 ——
    历史库、会话缓存、偏好都在同一棵 files 树下，路径写宽了等于全交出去。
  · **桥上的入口来自网页，而网页内容来自抓来的文章**，所以 Java 侧
    `install(path)` 拿 `getCanonicalPath` 比对，只认自己下载目录里的文件
    （`..` 和软链接绕不过去）。白名单一条比事后追查便宜。
  · **下完先校验字节数与 sha256**（GitHub 的资产元数据里直接带 `digest`，
    不用自己算）。企业网络出口会把长响应截断，截断的 apk 装上只报
    「解析包时出现问题」，用户完全想不到是下载的锅。校验通过才 `os.replace` 落位。
  更新检测**主要比版本号**（远端资产名里的版本号 vs 本机 `BuildConfig.VERSION_NAME`），
  版本号认不出来或两边一样（同一版本重新构建）时，才退回去比构建时间与安装时间。

### 本地为什么构建不了

Chaquopy 要求**构建机上的 Python 主次版本与应用完全一致**（这里是 3.12），
而且需要 Android SDK / JDK。本机是 Windows + Python 3.13，两者都不满足 ——
**这是预期行为**，不是配置错误。要本地构建，得先装 JDK 17 + Android SDK
并把 Python 3.12 装上。

想验证「除了编译之外的逻辑」，跑这两个就够（几秒钟，不需要任何安卓环境）：

```sh
.venv/Scripts/python.exe tests/test_apk_app.py     # 桥接层整链路 + 工程静态契约
.venv/Scripts/python.exe tests/test_apk_web.py     # 界面后端：真起本地服务 + 真发请求
```

`test_apk_web.py` 是**真的把服务跑起来、真的发 HTTP 请求**（假网络、假相册、真历史库），
所以界面这一层的逻辑在电脑上就能验完 —— 剩下验不到的只有两件事：
WebView 能不能加载 `127.0.0.1`、Python 能不能调进 `Gallery.publishDir`。
这两件用静态契约钉住（类名、方法名、参数顺序、相册目录名、清单里的网络配置）。

改了安卓工程里的东西之后，还有一个**反向验证**工具值得跑 —— 它逐条把源码拆坏，
确认那些断言**真的会拦得住**（不然测试全绿也只是"测试能跑"，不是"测试有用"）：

```sh
.venv/Scripts/python.exe tools/check_apk_reverse.py
```

它会临时改源码、跑测试、再立刻还原（备份放在 `_rv_backup/`，脚本启动时会先扫残留自动还原，
所以中途掐断也不会把源码留在拆坏状态）。预期结果是 **48 条全部有效**。
