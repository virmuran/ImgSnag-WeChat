# ImgSnag 安卓版

把「抓微信公众号文章原图」做成了手机上的一个普通 App：**在微信里点分享 → 选 ImgSnag → 图就进相册了**。

不用装 Termux，不用敲命令。

---

## 一、这个 APK 是怎么来的

**代码在你的电脑上，编译在 GitHub 的服务器上。**

原因很实在：安卓打包要 JDK + Android SDK + NDK + Gradle，全下来 2GB 起步，
在 Windows 上配好还得半小时；而 GitHub 的运行器**这些全都预装好了**，
公开仓库还免费、不限量。所以这里不放「打包脚本」，只有一个云端构建配置
（`.github/workflows/build-apk.yml`）。

你每次只需要**推送代码**，剩下的它自己做完。

---

## 二、怎么拿到 APK

### 方式 A：自动（推荐）

推送代码到 `main` 分支，只要改动涉及下面任何一处，就会自动开始构建：

- `android-apk/`（App 本体）
- `web_image_dl/`（抓取规则 —— 改了也要重打包，因为规则是同步进 APK 的）
- `version.py`（版本号）

构建大约 **3～6 分钟**。完成后打开：

> 仓库页面 → 右侧 **Releases** → 点最新那个 **「ImgSnag 安卓版 v…（自动构建）」**

**下载里面那个 `.apk` 文件就是。** 跟你下桌面版安装包是同一个地方、同一个操作。

### 方式 A2：正式发版时自动合体

在 GitHub 上 **Publish 一个正式版本 Release**（exe 和便携 zip 已传好）的那一刻，
构建会自动跑一次，并把 APK **塞进同一个 Release 页面** —— 于是那个版本下
exe、便携 zip、APK 三种形态并排，用户只需要记住一个下载入口。
（平时的日常推送仍然只更新 `apk-latest` 预发布位，两边互不打架。）

### 方式 B：手动触发

> 仓库页面 → **Actions** → 左侧选 **Build Android APK** → 右上 **Run workflow** → 绿色按钮

跑完同样去 Releases 拿。也可以在这次的构建记录最下方 **Artifacts** 里下
`ImgSnag-APK-x.y.z`（是个 zip，解开里面有 apk）。

### 怎么知道构建成功了

Releases 里出现了带新版本号的 `apk-latest` 预发布 = 成功。
如果没出现，去 Actions 里点开那次红色的构建，把 **报错那段**发我 —— 见文末「出问题了」。

## 三、怎么装到手机上

1. 在手机上打开那个 Release 页面（或者把 apk 用微信/QQ 传给自己，手机上下载）
2. 点开下载好的 `ImgSnag_1.9.0_android_arm64.apk`

**红米 / 小米（HyperOS）会拦一下**，这是正常的：

> 弹窗提示「为了安全，你的手机不允许安装未知应用」
> → 点弹窗里的 **设置** → 打开 **「允许来自此来源的应用」**
> → 返回，再点一次安装
>
> 如果系统还提示「此应用未经安全检测」，选 **「仍然安装」**。
> 装完后建议把这个开关**关回去**（安全习惯）。

首次安装可能还要确认「是否允许安装应用」，允许即可。

### 装不上？三个最常见原因

| 现象 | 原因 | 怎么办 |
|---|---|---|
| 提示「解析包出现问题」 | 下载不完整（多半是用内置浏览器下载被拦了） | 换用手机自带的浏览器/文件管理器重新下载 |
| 提示「应用未安装 / 与已有应用冲突」 | 之前装过**用别的密钥签名的**同名应用 | 先卸载旧的那个再装 |
| 提示「此应用与你的手机不兼容」 | 手机不是 arm64 架构，或系统低于 Android 10 | 红米 K80 是 arm64 + Android 15，正常不会遇到 |

## 四、怎么用

App 打开后是一个**网页界面**（为什么是网页，见文末「几个刻意为之的选择」）。

### 用法一：微信里直接分享（主用法）

> 微信打开文章 → 右上角 **…** → **分享**（或「复制链接」旁边的分享）
> → 在分享菜单里找到 **ImgSnag** → 点它

App 会打开并自动开始解析。**抓完停在预览页**，让你看一眼再决定存哪些。

分享菜单里应用很多，ImgSnag 可能在**第二页**或者要点「更多」。

### 用法二：自己贴链接

1. 复制文章链接（哪儿复制的都行）
2. 打开 ImgSnag，把链接粘进**顶部的输入框**，点「解析」
3. 同样抓完停在预览页，看完再存

### 界面长这样

```
┌────────────────────────────────┐
│ [ 粘贴公众号文章链接…    ]  解析 │
├────────────────────────────────┤
│ 找到 12 张图                    │
│  ┌──┐ ┌──┐ ┌──┐ ┌──┐           │  缩略图网格
│  │  │ │  │ │  │ │  │           │  点一下 = 看大图
│  └──┘ └──┘ └──┘ └──┘           │  点右上角圆圈 = 勾选
│   …                             │
├────────────────────────────────┤
│ 全选    已选 12 张    保存到相册 │
└────────────────────────────────┘
```

- **默认全选**：想全存就直接点「保存到相册」
- **点缩略图 = 看大图**，可以放大缩小、左右翻；大图页右上角也能勾选，还能**只存这一张**
- **点右上角的小圆圈 = 勾上／取消**（手机上把"看大图"和"勾选"分成两件事，
  免得想看的时候反而把它取消了）
- **全选／全不选**：几十张的时候不用一个个点

### 下载历史（左上角图标）

每次解析都会留一条记录，写着文章标题、时间、张数、有没有抓成功。

- **点开** = 重看上一批图（缩略图还在），也能**补存**当时没勾的
- **重抓** = 文章更新了，再解析一次
- **删掉** = 只删这条记录，相册里的图不动

> 只留最近 5 次，旧的自动清理。原图档和图本身不留（几十兆，没必要），
> 所以历史里点开看到的是缩略图 —— 想存原图就点「重抓」再存。

### 为什么抓完停在预览页，不直接进相册

以前是「分享进来 → 直接全抓进相册」。问题是文章里常混着表情包、二维码、
分割线小图这类不想要的图，抓完还得自己去相册一张张删。

现在**抓完先给你看，勾完再存** —— 相册里不会再进垃圾。

### 界面起不来怎么办

如果一直显示「正在启动…」或提示「界面没能启动」，遮罩上会留两个按钮：

- **重试**：再起一次
- **直接抓取**：不走网页 —— 读剪贴板里的链接 → 抓图 → 直接进相册
  （老路子，能用，但没有挑图这一步）

日志里 `❌` 开头的就是原因，**长按可以选中复制**，发我比截图好查。

## 五、图片存到哪儿

```
手机存储 / Pictures / ImgSnagWeChat / 2026-10-05_175300_文章标题 / img_01.jpg
                                              ├── img_02.png
                                              └── …
```

- **一篇一个文件夹**，名字是「日期_时分秒_标题」，按名字排序就是时间顺序
- 文件名按**真实格式**给扩展名（`.png` 就是 `.png`，不会都叫 `.jpg`）
- 存的是**原图档**（微信公众号图片的最高画质那一档），抓不到原图才退压缩档
- 手机相册会自动扫到，不用手动刷新

> 在「相册／图库」App 里通常能在 **相册 → 全部／Pictures → ImgSnagWeChat** 找到。
> 系统自带的「文件管理」里也能按上面那个路径翻到。

## 六、权限与隐私

- **只申请了一个权限：网络访问（INTERNET）**
- 没有申请任何「读写手机存储」权限 —— 写相册走的是系统的 MediaStore，
  Android 10 起应用新建自己的图片不需要存储权限
- 没有账号、没有统计、没有联网上传；图只从微信 CDN 下到你手机
- 抓的都是**公开文章**的图片

---

## 七、更新与卸载

**更新**：重复第三节的安装步骤即可，覆盖安装，**已抓的图不会丢**。
（所以签名密钥是固定的、提交在仓库里 —— 换密钥会导致新版本装不上旧版本。）

**卸载**：长按桌面图标 → 卸载。已经抓进相册的图片**不受影响**（它们在相册里，
不属于应用数据）。

## 八、出问题了怎么办

先说一件事：**我（写这个 App 的 AI）没法在你的手机上跑一遍** ——
手上没有 JDK、没有 Android SDK、没有安卓设备，本机连编译都做不到。
所以第一次装上很可能有一两个小毛病要修。这是预期内的，不是白折腾。

请按这个顺序给我信息：

1. **构建失败**（Releases 里没出现 APK）→ 把 GitHub Actions 那次红色构建里
   最后 30 行报错贴给我
2. **装不上** → 告诉我弹窗的**原文**
3. **装上了但打不开/闪退** → 告诉我大概是点开就退，还是进了界面再退
4. **分享菜单里找不到 ImgSnag** → 试试用「复制链接 → 粘进输入框 → 解析」这条路，
   能抓说明是分享入口的问题；另外告诉我你是在微信里点「分享」还是「复制链接」
5. **抓不到图** → 把日志里那段文字复制发我（`❌` 开头的那几行最关键）
6. **打开一直转圈、或者界面白屏** → 先点「重试」；还不行就点「直接抓取」
   （它不走网页，一定能用）。然后把这行日志发我 ——
   白屏多半是手机不允许 App 连它自己的本机地址（127.0.0.1），日志里会写明。

## 九、给想改代码的人（工程说明）

### 目录

```
android-apk/
├── app/
│   ├── build.gradle.kts              构建配置（compileSdk 36 / minSdk 29 / 只带 arm64-v8a）
│   ├── proguard-rules.pro            压缩规则（当前没开压缩，留着备用）
│   └── src/main/
│       ├── AndroidManifest.xml       权限 + 「分享」入口 + 回环明文放行
│       ├── java/com/virmuran/imgsnag/
│       │   ├── MainActivity.java     外壳：起本地服务、装 WebView、投递分享
│       │   └── Gallery.java          把图写进系统相册（MediaStore）
│       ├── python/
│       │   ├── imgsnag_web.py        ★ 手写：界面后端（本地服务 / 会话 / 历史）
│       │   ├── webui.py              ★ 手写：整个页面（HTML+CSS+JS 单文件）
│       │   ├── imgsnag_android.py    ★ 手写：桥接层（网络 / 证书 / 人话化）
│       │   ├── imgsnag.py            ← 自动同步，别改
│       │   └── web_image_dl/         ← 自动同步，别改
│       └── res/                      布局、文案、颜色、启动图标、网络安全配置
└── keystore/imgsnag.p12              自用签名密钥（固定，见 keystore/README.md）
```

### 三层分工

| 层 | 负责 | 为什么不放别处 |
|---|---|---|
| Java | 外壳：起服务、WebView、接收分享、写相册 | 这些是安卓平台特有的能力 |
| `imgsnag_web.py` + `webui.py` | 界面：本地服务 + 网页（网格／大图／历史） | 手写；**而且网页在电脑上就能验**（没模拟器也能测） |
| `imgsnag_android.py` | 网络（urllib）、证书、把结果拼成人话 | 手写；平台相关的黏合层 |
| `imgsnag.py` + `web_image_dl/` | 抓取与站点规则 | **与桌面版、Termux 版是同一份文件** |

`web_image_dl/sites/weixin.py`（微信原图档、去水印、正文顺序）是这套程序最值钱也
最容易失效的部分。它被 `android/sync_core.py` **自动同步**到三个地方：

```
web_image_dl/  ──sync_core.py──▶  android/app/                      （Termux 版）
              ──sync_core.py──▶  android-apk/app/src/main/python/     （APK）
```

改了规则之后**必须**跑一次：

```sh
.venv/Scripts/python.exe android/sync_core.py
```

忘了跑也不会出事 —— `tests/test_apk_app.py` 第一条就是逐字比对副本，
不同步当场变红，CI 上也会先跑它再打包。

### 几个刻意为之的选择

- **界面是一个网页，不是安卓控件**。图片网格、点开看大图、缩放、翻页，浏览器天生都有；
  用安卓控件从头写至少要几百行，而且**本机一行都验不了**（没模拟器、没真机）。
  改成网页之后，抓取跑在本地服务上（只绑 `127.0.0.1`），页面在电脑上就能打开、
  能点、能截图 —— 把「只能靠真机发现」的部分压到最小。代价是手机上多了一个
  「App 能不能连自己的回环地址」的前提，所以「直接抓取」那条老路留着兜底；
  清单里也只给回环地址放行了明文 HTTP（`res/xml/network_security_config.xml`），
  没有全局开口子。
- **一个 pip 包都不装**。Chaquopy 装包要走它自己的仓库、还得为 arm64 现编，
  是整条构建链路最容易挂的地方；而 `web_image_dl/` 本来就是零第三方依赖的，
  联网用自带的 `urllib` 就够。
- **不做代码压缩**（`isMinifyEnabled = false`）。Chaquopy 的 Python 靠反射调进
  Java，R8 看不见这些调用。省几 MB 换来「某个功能上线后莫名失效」不划算。
- **minSdk 29**。写相册用的 MediaStore `RELATIVE_PATH` 要 Android 10 起；
  有这个就不需要任何存储权限。再往下兼容要写另一套老 API，对自用工具不值当。
- **版本组合锁死**（Chaquopy 17.0.0 + AGP 8.13.1 + Gradle 8.13）。
  这是 Chaquopy 17.0.0 官方 demo 自己的配置。**不要顺手升 AGP** ——
  Chaquopy 插件和 AGP 内部 API 绑得很紧，升级后报的错通常很难看懂。
- **版本号从 `version.py` 读**，不手写。APK 上显示的版本和桌面版对得上。

### 本地为什么构建不了

Chaquopy 要求**构建机上的 Python 主次版本与应用完全一致**（这里是 3.12），
而且需要 Android SDK / JDK。本机是 Windows + Python 3.13，两者都不满足 ——
**这是预期行为**，不是配置错误。要本地构建，得先装 JDK 17 + Android SDK
并把 Python 3.12 装上。

想验证「除了编译之外的逻辑」，跑这两个就够（几秒钟，不需要任何安卓环境）：

```sh
.venv/Scripts/python.exe tests/test_apk_app.py     # 桥接层整链路 + 工程静态契约
.venv/Scripts/python.exe tests/test_apk_web.py     # 界面后端：真起本地服务 + 真发请求
```

`test_apk_web.py` 是**真的把服务跑起来、真的发 HTTP 请求**（假网络、假相册、真历史库），
所以界面这一层的逻辑在电脑上就能验完 —— 剩下验不到的只有两件事：
WebView 能不能加载 `127.0.0.1`、Python 能不能调进 `Gallery.publishDir`。
这两件用静态契约钉住（类名、方法名、参数顺序、相册目录名、清单里的网络配置）。

改了安卓工程里的东西之后，还有一个**反向验证**工具值得跑 —— 它逐条把源码拆坏，
确认那些断言**真的会拦得住**（不然测试全绿也只是"测试能跑"，不是"测试有用"）：

```sh
.venv/Scripts/python.exe tools/check_apk_reverse.py
```

它会临时改源码、跑测试、再立刻还原（备份放在 `_rv_backup/`，脚本启动时会先扫残留自动还原，
所以中途掐断也不会把源码留在拆坏状态）。预期结果是 **26 条全部有效**。
