## 支持哪些站点

本工具不做通用网页图片下载器，只对选定站点做专项适配：按「结构是否稳定、是否存在明确的原图路径、反爬强度」逐站点评估，达标才接入。

| 站点 | 提取内容 | 接入理由 |
|---|---|---|
| **微信公众号** | 文章正文图、无水印原图档 | 结构多年稳定，静态 HTML，正文图本身不带水印 |
| **cosmeitu.com** | 作品页全部正文图、去压缩参数取原图 | 页面自带图片编号（按编号定序最可靠），图床无防盗链 |

> **新增站点的成本 = 新增一个文件 + 注册表加一行**：站点逻辑集中在 `web_image_dl/sites/`，
> 一个站点一个文件；公共链路（界面、命名、图库、下载、历史）与具体站点无关。

## 功能特性

- 📐 **原图画质**：自动请求原图档而非压缩档，同一张图体积可达数倍，默认开启
- 🚫 **屏蔽尺寸**：右键屏蔽封面、头像等噪音图，下次解析自动过滤，随时可撤销
- 🖼 **大图预览**：缩略图条 + 可缩放拖动的大图，支持 1:1 核对画质
- 🗂 **图库归档**：每次下载独立文件夹，按文章标题命名，多篇互不混淆
- 🔢 **顺序正确**：导出按正文顺序连续编号，图集无需手动重排
- 🧹 **智能去重**：多 CDN 节点重复图自动合并，头像与装饰图自动排除
- 🔄 **格式任选**：原格式 / JPG / PNG / WebP 一键转换
- ©️ **来源标注**：界面标注图片来源，下载批次附带来源说明
- 👀 **历史回看**：下载过的批次直接在软件内翻看，无需另开文件夹
- 💾 **偏好记忆**：窗口、排序、格式等设置下次启动原样恢复
- 📥 **托盘常驻**：关闭行为可选（最小化 / 退出），下载不因关窗中断
- ⬆ **应用内更新**：检查、下载、安装新版本一步完成
- 🔒 **纯本地**：不收集、不上报任何数据，仅更新检查访问 GitHub

各功能的详细操作见下文 [快速上手](#快速上手)。

## 下载与安装

> 本仓库只提交**源码与打包配置**。发行产物请前往 [Releases](https://github.com/virmuran/ImgSnag/releases)。
> 若暂无可用发行版，可按下文「从源码运行」自行运行。

| 文件 | 平台 | 说明 |
|---|---|---|
| `ImgSnag_X.X.X_setup.exe` | Windows | 安装向导（简体中文），下一步装完，开始菜单 / 桌面快捷方式、控制面板卸载 |
| `ImgSnag_X.X.X_portable.zip` | Windows | 解压即用、免安装、无需管理员权限，适合 U 盘或受管控的公司电脑 |
| `ImgSnag_X.X.X_android_arm64.apk` | Android | 与桌面版同源解析；在微信里「分享 → ImgSnag」，图片直接进入系统相册 |

每个版本页面下三个文件并列，按平台选用即可。桌面两种发行均无需安装 Python。**用户数据保存在用户自己的账户下**（见下表；界面偏好写入注册表），安装版卸载**不会**删除下载历史与过滤配置。

用户数据位置：

| 内容 | 位置 |
|---|---|
| **下载的图片（图库）** | `图片\ImgSnag\<日期_时分秒_文章标题>\`（系统「图片」目录下） |
| 下载历史（SQLite） | `~/.imgsnag/history.db` |
| 屏蔽尺寸配置 | `%APPDATA%\ImgSnag\blocked_sizes.json` |
| 界面偏好（窗口大小、排序、图库位置等） | 注册表 `HKCU\Software\ImgSnag` |

> 图库目录是普通文件夹，可整体搬移或备份；搬走后历史中的「打开」会标为「本地已删除」，放回原路径即可恢复。

## 从源码运行

```bash
git clone https://github.com/virmuran/ImgSnag.git
cd ImgSnag

python -m venv .venv
.venv\Scripts\pip install -r requirements.txt     # Windows
.venv\Scripts\python main.py
```

需要 Python 3.11+。依赖只有两个：`PySide6-Essentials`（Qt 基础模块）和 `requests`。

## 手机版

两个手机版本，**解析图片的规则与桌面版是同一份代码**，因此原图档、去水印、正文顺序等能力三端完全一致，差别仅在于结果的交付方式。

### 安卓 App（推荐）

安装方式与普通安卓应用一致：在微信里 **分享 → ImgSnag**，图片直接进入系统相册。无需 Termux，无需命令行。

**APK 由 GitHub Actions 自动编译**，正式发版时自动补进同一个版本页面：一个 Release 下并列 exe、便携 zip、APK 三种形态，只需从 **Releases** 下载最新版本。云端编译的原因、安装步骤与红米机型注意事项见 **[`android-apk/README.md`](android-apk/README.md)**。

### Termux 命令行版

无图形界面，通过命令行与「分享 → Termux」使用。安装与使用见 **[`android/README.md`](android/README.md)** —— 内含安卓平台的完整步骤，以及红米 / HyperOS 机型需注意的两项限制（省电限制、存储权限）。

| | 安卓 App | Termux 版 |
|---|---|---|
| 使用方式 | 分享菜单，或点按按钮 | 分享 → Termux，或执行命令 |
| 上手成本 | 安装 APK | 安装 Termux + 运行安装脚本 |
| 独有能力 | 图片自动进入系统相册 | `--list` 干跑、指定输出目录 |

## 快速上手

### 1. 解析

把**文章链接**（例：`https://mp.weixin.qq.com/s/...`）粘进输入框，点「解析图片」或按 `Ctrl+Enter`。粘贴内容中混有其他分享文字不影响解析，链接会被自动提取。

少数情况无法直接解析时，可改用 HTML 源码模式：浏览器按 `F12` → 元素面板 → 右键 `<html>` → 复制 → **复制 outerHTML**，粘进同一个输入框后点「解析图片」；「粘贴HTML」按钮可直接从剪贴板读入。

### 2. 挑选

- **原图画质**（默认开启）：自动请求原图档而非页面中的压缩档，同一张图体积可达数倍；解析时状态栏显示本次合计体积，原图档不可用时自动回退压缩档
- **过滤小图与装饰**（默认开启）：自动隐藏三类非正文图 —— 最长边 ≤ 200px 的小图、小于 10KB 的透明 PNG、以及用户右键标记过的尺寸。隐藏仅是不显示、不勾选，不删除任何文件；取消勾选即可全部显示
- **右键任意缩略图 → 屏蔽此尺寸**：把该图片的尺寸加入黑名单，下次解析直接过滤，同时也是「过滤」第三条规则的来源。**屏蔽可在「历史」页底部撤销**（面板列出分类、尺寸与命中次数，支持逐条恢复 / 全部恢复；撤销后当前页面中被该规则拦下的图会立即恢复并自动勾选）
- **解析可中途取消**：再次点击按钮（此时显示为「取消解析」）即可中止，已下载的图片会保留，仍可勾选保存
- 顶部可切换排序（默认顺序 / 名称 / 尺寸 / 分辨率）；「全选」按钮一键批量勾选或取消（文案在「全选 / 全不选」间切换）
- 被隐藏的图不会消失：缩略图条底部显示「已隐藏 N 张 · 点此显示」，可随时展开或收起；重复图与被过滤的小图在卡片角上带文字角标
- 输入框内按 **Enter** 亦可解析（Ctrl+Enter 同效）；粘贴 HTML 源码请用「粘贴HTML」按钮

### 3. 下载

选好保存格式后点「下载」。**无需选择目录**，图片自动存入图库内的专属文件夹：

```
图片\ImgSnag\
├─ 2026-09-18_164633_秋天的第一杯奶茶\     ← 本次下载的 8 张图
│   ├─ img_01.jpg
│   ├─ img_02.png
│   └─ …
└─ 2026-09-18_171205_城市黄昏随拍\         ← 另一篇文章，独立存放
```

- 文件夹名为 `日期_时分秒_文章标题`，按名称排序即为时间顺序；同一秒内重复下载会自动加 `_2`
- 标题无法获取（或含非法字符被清空）时使用站点兜底名（如微信的「微信图片」），不会以空名称创建目录
- 需要把**这一次**保存到别处：动作栏的「另存」（仍会新建专属子文件夹）
- 查看图片保存位置：动作栏的「图库」，优先打开最近一次落盘的文件夹；想换地方在侧边栏「设置」→「图库保存位置」里改（默认在系统「图片」下的 `ImgSnag`）
- 复制文章名：动作栏的「复制」输出**不带日期编号**的名称 ——
  图库文件夹名为 `2026-09-18_164633_秋天的第一杯奶茶`，复制结果为「秋天的第一杯奶茶」。

状态栏显示进度与结果统计（共几张、几张有效、几张重复）。写盘与格式转换在后台进行，
图多时界面保持响应，按钮上显示「保存中 3/20」等进度。

### 4. 历史

「历史」页记录每次解析与下载（已解析 / 已下载 / 部分成功 / 失败），每条记录均可**再次解析**、**打开保存目录**、**删除**，也可一键清空。「保存路径」列显示该次的批次文件夹名（日期_时分秒_标题），完整路径见悬停提示。

本地文件夹被清理或搬走时，该行标注**「本地已删除」**并禁用「打开」按钮。

页面底部为**已屏蔽的尺寸**面板：列出每条屏蔽的类别（UI 装饰 / 头像 / 封面横幅）、尺寸、已过滤张数与加入时间。误屏蔽时点「恢复」即可撤销，当前页面中被该规则拦下的图会立即恢复并勾选；点「全部恢复」可一次清空。

### 5. 托盘与关闭

点窗口右上角的 ✕ 时三选一：**最小化到托盘**（继续在后台运行，下载不中断）/ **直接退出** / **取消**。
勾选「记住我的选择」后不再询问；之后可在托盘图标右键菜单 →「关闭窗口时」中修改，侧边栏「设置」页里也能改（两处是同一个设置，改哪边都一样）。

托盘图标**单击或双击**均可唤回窗口，最大化状态原样还原。右键菜单还包含「打开图库」与「退出 ImgSnag」——
「退出」为真正退出程序，与点 ✕ 选「直接退出」等价。

> 系统托盘不可用的环境（部分受限或无桌面 shell 的机器）无法收进托盘，此时点 ✕ 会直接退出，
> 不会出现窗口消失而进程仍在的情况。

## 常见问题

**Q：解析到 0 张图？**
先勾选「补充Script扫描」重新解析；仍为空时，多为文章需登录或验证后才能查看，或文章中确实没有图片。

**Q：下载的图还是只有几百 KB？**
先确认「原图画质」已勾选。微信对同一张图提供多个画质档位，正文 HTML 中一般为压缩档（地址中的 `/640`），本程序会自动改写为原图档（`/0`）。

压缩档与原图档的差异，以一篇真实的 8 图文章实测（`tools/e2e_article_download.py`）：

| | 压缩档（`/640`） | 原图档（`/0`） | 提升 |
|---|---|---|---|
| 单图体积 | 93.4 – 175.3 KB | 363.8 – 748.9 KB | 3.17 – 4.29 倍 |
| 单图分辨率 | 1080×1440 | 2155×2873 ~ 2560×3413 | 3.98 – 5.62 倍像素 |
| **全篇 8 张合计** | **1131 KB（约 1.1 MB）** | **4372 KB（约 4.4 MB）** | **3.86 倍** |

这就是「下载的图只有几百 KB、浏览器里另存却有好几 MB」的原因：微信正文 HTML 里给的地址指向压缩档，本程序会改写为原图档后再下载。

`/0` 已**验证为画质上限**，不存在更高的档位：

- `/1080`、`/1280`、`/2000`、`/3000` 等档位一律被 CDN 拒绝（HTTP 400），合法档位只有 `/0` 和 `/640`
- 去掉尺寸段等同于 `/0`
- 把 CDN 前缀换成 `mmbiz` / `mmbiz_png` 等，只会拿到 0.2 KB 的"未经允许不可引用"占位图（此类占位图会被程序按最小体积阈值过滤）

因此，改用原图档后体积仍然不大时，说明微信对**该图本身**仅提供到该画质 —— `/0` 即为上限，没有更高的档位。

关于水印版与无水印版：`picture_page_info_list` 中每个 item 有两条 `cdn_url`，是**两个分别上传的文件**（文件 ID 不同），一条无水印、一条带水印。实测两者的 `/0` 档体积基本相当，差值绝大多数在 2% 以内（8 图文章中水印版 4 张略大 0.4%–1.8%、4 张略小；另一篇 5 图文章中最大的一张水印版大 13%）。即**不存在「几 MB 的带水印原图」**：取无水印版不损失画质，换带水印版也得不到更大的图。本项目只取无水印版，无任何画质代价。

如需实测某篇文章的差异，或自行复核上述数字：

```bash
.venv\Scripts\python.exe tools\e2e_article_download.py <文章链接>          # 端到端运行生产链路，对比新旧画质
.venv\Scripts\python.exe tools\probe_wechat_quality.py <文章链接>          # 仅测档位差距，不落盘
.venv\Scripts\python.exe tools\probe_max_quality.py <图片链接或文章链接>    # 穷举地址写法，确认画质上限
```

**Q：保存的图会不会覆盖上次下载的？**
不会。v1.7.0 起每次下载都进入**独立的批次文件夹**（`日期_时分秒_标题`），同秒重名自动加 `_2`；同一文件夹内的同名文件加 `_1` / `_2` 后缀。

**Q：为什么图片不在「下载」文件夹里？**
设计如此。「下载」目录使用频繁、容易被整体清空，图集存放其中可能被一并删除。现统一存入 `图片\ImgSnag\`，历史中的「打开」只要文件夹仍在即可使用。需要改用其他位置时用动作栏的「另存」。

**Q：历史里的「打开」是灰的？**
该次下载的本地文件夹已不存在（被清理或搬走）。程序无法恢复文件，将文件夹放回原路径即可恢复。

**Q：导出的 `img_01.jpg` 是正文第一张吗？**
是。输出顺序按正文顺序（合并 ppi 数组顺序与正文标签出现顺序），因此连续编号即阅读顺序，漫画或长图无需手动重排。

**Q：能下载其他网站的图片吗？**
只支持已明确适配的站点，目前为**微信公众号**与 **cosmeitu.com**；其他站点的链接会直接提示不支持。理由见 [支持哪些站点](#支持哪些站点)。

**Q：下载的图有水印吗？**
微信**正文图**本身不带水印，本项目还会优先取 `picture_page_info_list` 中的无水印原图。若混入带水印的**封面图**，在缩略图上右键「屏蔽此尺寸」即可拦下，下次解析同类尺寸自动过滤。

**Q：安装时提示「错误 5：拒绝访问」？**
少数受管控的公司电脑会拦截 Temp 目录写入。可右键「以管理员身份运行」，或改用**便携版**（不写临时目录、无需管理员权限）。

**Q：卸载会删掉历史记录吗？**
不会。用户数据位于用户目录，卸载程序不会删除，覆盖升级也不会丢失。

**Q：点「检查更新」提示连不上 GitHub？**
`api.github.com` 在部分网络环境下无法访问，公司网络常直接限制。这不影响其他功能，手动下载新版本即可（每次发布均附安装包与便携包）。启动时的自动检查为静默执行：连接失败不作任何提示。

**Q：使用加速器 / 公司网络能上网，为什么仍提示连不上？**
v1.8.2 起已修复。此类网络会做 TLS 转发（用自装根证书重新签发流量），而 Python 的 `requests` 仅信任自带的 certifi 证书列表，导致「证书未受信任」被误报为「网络不通」。程序现将 **Windows 证书存储中的根证书合并进 CA 包**后再发起请求（本机实测：对端证书由加速器根证书签发，合并后 1.2 秒内正常返回）。若仍失败，提示会明确指出是证书问题，而非笼统报网络不通。

## 打包发版

```bash
# 双击 build.bat 亦可（venv 不存在时会自动创建并安装依赖）
.venv\Scripts\python.exe build_release.py
```

一条命令完成：**PyInstaller onedir → Inno Setup 安装包 → 便携 zip（LZMA）**，产物在 `installer/` 与 `dist/`。

- 采用 **onedir** 而非 onefile：不向 `%TEMP%` 解压，启动更快、杀软误报更少，也不受受限环境的 Temp 目录限制
- 版本号**唯一手写在 `version.py`**，构建脚本自动同步到 `.iss`；脚本内置闸门，格式不合法或该号已打过包都会中断打包
- `build.bat` 支持传参，`--skip-build` 可跳过 PyInstaller 只重做安装包

欢迎提交 Issue 和 Pull Request。改动提取逻辑（`extractor.py`）时，请一并说明对应的页面结构特征，便于回归验证。

改动后请先跑回归测试（十二个文件、1825 项，离屏运行、无需显示器）：

```bash
.venv\Scripts\python.exe tests\run_all.py
```

发现某篇文章解析结果异常时，先用 `tools/` 中的诊断脚本确认页面结构，避免凭猜测修改正则。
